# Career Atelier

[English README](README.md)

Career Atelier는 이미 구독 중인 ChatGPT·Claude·Gemini를 그대로 써서 채용 준비를
도와주는, 직접 설치해 쓰는 구직 작업실입니다. 토큰당 과금되는 API 키는 쓰지
않습니다.

이 문서는 "직접 돌려보려는 사람"과 "같이 만들어 보려는 사람" 모두를 위한
것입니다. 설치부터 하려면 [시작하기](#시작하기)로, 왜 이렇게 만들었는지부터
알고 싶으면 [이렇게 만든 이유](#이렇게-만든-이유)로 가세요.

## Career Atelier가 뭔가요?

지원할 때마다 같은 일을 반복하게 됩니다. 이 회사가 정확히 뭘 하는지, 최근에 뭘
내놨는지, 내 경험 중 뭐가 이 자리와 맞는지, 비슷한 문항에 예전에 뭐라고 썼는지.
Career Atelier는 그 맥락을 한곳에 모아 두고, 일곱 비서가 그 위에서 일하게 합니다.

| 비서 | 하는 일 | 실행 |
|---|---|---|
| 루미 | 관심 분야 최신 뉴스 조사 | Codex |
| 모카 | 내 프로필에 맞는 채용공고 탐색 | Codex |
| 솔 | 기업·직무를 공식 자료 중심으로 조사 | Claude Code |
| 뮤즈 | 내가 기록한 경험만 근거로 자소서 초안 작성 | Codex |
| 렌즈 | 과장·근거 누락 검수 | Claude Code |
| 에코 | 공고 기반 예상 면접 질문 생성 | Claude Code |
| 소제목 | 완성된 자소서의 문항 소제목 제안 | Antigravity(Gemini) |

이 비서들 주위에 작업실이 있습니다. 전형 단계별로 합불을 따로 기록하는 지원
캘린더, 경험 아카이브, 버전이 남는 자소서 에디터, 면접 훈련실, 그리고 각 비서의
시스템 프롬프트를 직접 고치고 이전 버전으로 되돌릴 수 있는 명령 실험실입니다.

## 왜 이걸 쓰나요?

- **토큰 단위 과금이 없습니다.** 이미 구독료를 내고 있는 CLI 도구를 통해 돌립니다.
  러너가 자식 프로세스에서 `OPENAI_API_KEY`·`ANTHROPIC_API_KEY` 같은 변수를
  제거하고, 실행 전에 각 CLI가 구독 로그인 상태인지 확인하며, 유료 초과 사용으로
  넘어가는 대신 그 자리에서 멈춥니다.
- **로그인 정보가 내 컴퓨터를 벗어나지 않습니다.** 클라우드 쪽에는 AI 자격증명이
  아예 없습니다 — 있으면 빌드가 실패하도록 막아 뒀기 때문에 있을 수가 없습니다.
- **데이터는 내 것입니다.** 사람마다 자기 Supabase 프로젝트를 쓰고, RLS로 본인
  행만 접근되며, 클라우드가 날아가도 글이 함께 사라지지 않도록 로컬 폴더 백업을
  켤 수 있습니다.
- **지어내지 않습니다.** 작성 비서는 실제로 기록해 둔 경험만 근거로 쓸 수 있고,
  존재하지 않는 근거 id는 저장 전에 걸러집니다.

## 구조

```
브라우저 ──── Vercel (web/) ─────┐
                                 │ Supabase: Postgres + Auth + RLS
내 컴퓨터 ─── runner/ ───────────┘
      └─ codex / claude / agy   (구독 OAuth, 이 기기 안에만)
```

웹 앱은 비서를 직접 실행하지 않습니다. 작업 큐에 한 줄 넣을 뿐입니다. 내 컴퓨터에서
내 계정으로 로그인해 도는 러너가 그 작업을 집어 컨텍스트를 만들고, 알맞은 CLI를
실행하고, 결과를 되돌려 저장합니다. 러너를 꺼도 사이트는 그대로 쓸 수 있고, 새
비서 실행만 못 하게 됩니다.

## 시작하기

**Node.js 22 이상**, 무료 [Supabase](https://supabase.com) 프로젝트, 그리고 AI CLI
구독이 최소 하나 필요합니다.

```bash
git clone https://github.com/tkv00/Career-Atelier-AI-Context-Pack.git
cd Career-Atelier-AI-Context-Pack
npm run setup
```

`npm run setup`은 Windows·macOS·Linux에서 똑같이 동작합니다. 필요한 도구를
확인하고, Supabase 프로젝트를 연결하고, 데이터베이스 마이그레이션을 적용하고,
환경변수 파일 두 개를 대신 만들어 줍니다.

그다음 양쪽을 실행합니다.

```bash
cd web    && npm install && npm run dev     # http://localhost:3000
cd runner && npm install && npm run login && npm run start
```

**가장 먼저 가입한 계정이 그 인스턴스의 소유자**가 되고, 이후 가입은 전부
거부됩니다. 관제실 화면에서 러너를 한 번 승인해 주면 작업을 받기 시작합니다.

OS별 안내와 AI CLI 로그인까지 포함한 전체 설명은
**[docs/USER-GUIDE.md](docs/USER-GUIDE.md)** 에 있습니다.

### 웹 앱 배포

Vercel 프로젝트의 Root Directory를 `web/`로 잡고 환경변수 두 개
(`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`)만 넣으면 됩니다.
service_role 키나 AI 제공자 키는 넣지 마세요 — 일부러 빌드가 거부합니다.
자세한 내용은 [docs/V2-SETUP.md](docs/V2-SETUP.md).

## 데이터 백업

Supabase 무료 플랜은 한동안 안 쓰면 프로젝트를 정지시키기도 하고, 클라우드 DB
하나만 믿으면 다시 쓰기 힘든 글이 통째로 날아갈 수 있습니다. 관제실의 러너 항목에서
**로컬 폴더 자동 백업**을 켜고 절대 경로를 하나 지정하세요. 러너가 6시간마다 전체
데이터를 JSON으로 그 폴더에 저장합니다. 하루에 한 파일이라 폴더가 무한정 커지지
않습니다.

백업은 브라우저가 아니라 러너가 씁니다 — 웹페이지는 내 디스크의 임의 폴더에 파일을
쓸 수 없기 때문입니다.

## 이렇게 만든 이유

가장 흔한 설계는 전부 서버에 올리고 OpenAI·Anthropic API를 호출하는 것입니다.
두 가지 이유로 그렇게 하지 않았습니다.

**인증이 기기에 묶여 있습니다.** Codex와 Claude Code는 로컬에 저장된 OAuth 세션으로
인증합니다. 이걸 서버로 옮기려면 오래 사는 자격증명을 서버 환경변수에 넣어야 하고,
그 서버가 뚫리면 그 계정들이 함께 뚫립니다.

**종량제 API는 비용 구조를 바꿉니다.** 이 프로젝트의 목적은 이미 내고 있는 구독료를
쓰는 것입니다. 조용히 토큰 과금으로 넘어갈 수 있는 설계는 언젠가 예상 못 한 청구서를
만듭니다. 그래서 러너는 경고만 하는 게 아니라 그 경로 자체를 막습니다.

그 결과가 지금의 분리입니다. 데이터는 갖고 자격증명은 갖지 않는 클라우드 면과,
자격증명을 갖고 모델을 돌리는 로컬 면.

## 기여하기

기여를 환영합니다. 개발 환경 설정과 PR 기준은 [CONTRIBUTING.md](CONTRIBUTING.md)에
있습니다. 각자 자기 Supabase 프로젝트로 개발하므로 망가뜨릴 공용 개발 DB가 없습니다.

시작하기 좋은 곳:

- 러너에 아직 macOS 기준으로 짜인 부분이 남아 있습니다. Windows·Linux 실제 테스트가
  특히 도움이 됩니다.
- 비서는 `runner/context-pack.mjs`와 `runner/providers/`에 정의돼 있습니다. 새
  제공자를 붙이는 건 거기 파일 하나를 추가하는 일입니다.
- 면접 훈련실과 명령 실험실 화면의 검증이 가장 얇습니다.
