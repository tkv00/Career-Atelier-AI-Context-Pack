05 / SYSTEM DESIGN · PROCESS

필요한 근거만, 역할이 분명한 입력으로

뮤즈는 문항·직무·수정 요청에 맞는 경험을 고릅니다. 고정한 경험과 기존 인용을 먼저 지키고, 나머지는 점수와 문자 예산으로 선택합니다.

선별 정책: lexical-evidence-v1

검색어는 문항·직무·공고 설명·요구 역량·수정 요청에서 만들고, NFKC 정규화와 소문자 변환 후 중복을 제거합니다. 검색어가 직렬화된 경험에 있으면 1점, 제목에 있으면 3점, 태그에 있으면 4점을 추가합니다.

고정·필수 경험을 먼저, 이후 점수 내림차순과 ID 순으로 정렬합니다. 직렬화한 경험 사이 구분자까지 포함해 기본 16,000자 예산을 계산합니다. 양의 점수가 있거나 필수인 항목을 선택하고, 선택 항목이 없을 때는 예산에 맞는 첫 경험을 대체 선택합니다.

선별 결과에는 정책 버전·문자 수·선택 ID·점수·일치어·제외 이유를 남깁니다. 로컬 context-selection.json과 실행 이벤트의 context_selection에서 확인할 수 있습니다. 글자 수 감소와 모델이 보고한 토큰 감소는 다른 지표입니다.

문서 변환과 출력 검증

PDF·Office 원본은 로컬 MarkItDown으로 Markdown화한 뒤 작업에 필요한 텍스트로 다룹니다. 가져오기는 정형 파서와 코드 검증을 우선하며, 필요한 자유 서술 조각이나 메타데이터 보정에 CLI를 사용합니다. 모든 문서가 항상 모델에 통째로 전달되는 것은 아닙니다.

schema-compat.mjs가 제공자별 스키마 차이를 정규화합니다. 뮤즈 출력의 evidence[].experience_id를 선택된 카드 ID와 대조하고, 어긋난 인용은 evidenceViolations로 표시합니다. 이 검사는 모든 문장의 사실성을 보장하거나 위반 초안을 자동 폐기하는 검사는 아닙니다. 렌즈의 검수와 사용자의 확인이 이어집니다.
