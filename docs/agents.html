02 / SYSTEM DESIGN · PROCESS

일곱 비서가 작업을 넘기는 방식

비서는 역할별 작업 핸들러입니다. 로컬 러너가 큐에서 일을 하나씩 가져와 선택된 제공자로 실행하고, 성공한 결과를 다음 단계에 전달합니다.

하나의 러너, 역할별 핸들러

비서담당 작업호출 경로
루미관심 분야 뉴스news
모카채용공고 탐색jobs
솔기업·직무 조사company
뮤즈경험 기반 작성·수정writer
렌즈사실·과장·직무 적합성 검수review
콤마문항 소제목subtitle
에코면접 질문 준비interview

제공자·모델·추론 강도는 비서별 설정으로 선택합니다. 일곱 비서가 항상 동시에 실행되는 구조는 아닙니다. 한 러너의 동시 실행은 1개이며 CLI 실행 시간은 최대 15분으로 제한됩니다.

연쇄 실행과 멈추는 조건

pipeline_id가 있는 작업은 성공 후 continuePipeline으로 다음 작업을 등록합니다. 개별 실행은 단독으로 끝납니다. 뮤즈는 방금 만든 초안을 draftOverride로 렌즈에 넘겨, 사용자가 아직 본문에 반영하지 않았더라도 그 초안을 검수하게 합니다.

실행이 실패·차단되거나 후속 단계에 필요한 출력이 없으면 체인은 멈춥니다. 일반 실행 실패는 자동 재시도하지 않습니다. 루미·모카의 검색 미호출 또는 저장 가능한 결과 0건은 예외적으로 새 작업을 최대 한 번 등록합니다.

검색과 구조화 호출의 분리

Codex를 쓰는 루미·모카는 검색 전용 호출에서 실제 검색 완료 이벤트를 확인하고, 조사 메모를 별도의 구조화 호출에 전달합니다. 두 번째 호출은 웹 검색을 끄고 스키마에 맞는 JSON을 만듭니다. 모든 비서·제공자가 항상 두 번 호출되는 것은 아닙니다.

진행 이벤트는 200ms 간격으로 묶어 저장합니다. 완료 처리는 CLI 종료뿐 아니라 결과 처리·저장 단계까지 반영하며, 실패 사유는 작업과 실행 기록에서 확인할 수 있습니다.
