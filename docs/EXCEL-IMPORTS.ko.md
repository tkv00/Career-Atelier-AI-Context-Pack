# 엑셀 자료 가져오기

사용자마다 시트 이름, 제목 위치, 헤더, 스킬 열이 다르므로 하나의 템플릿을 요구하지 않습니다. XLSX를 업로드하면 로컬 러너가 셀을 읽고, 시트마다 헤더와 자료 분류를 찾아 검토 후보를 만듭니다. 분석 결과는 사용자가 저장하기 전까지 실제 이력에 반영되지 않습니다.

## 사용 순서

1. **자료 가져오기 → 파일 업로드**에서 XLSX를 선택합니다.
2. **분석하고 미리보기**를 누릅니다. 표 본문은 규칙으로 읽고, 경험의 제목·대표 역량은 로컬 AI로 정리합니다.
3. **설정을 바꾸어 다시 분석 → 시트 원본과 열 매핑**에서 자동으로 찾은 영역을 확인합니다.
4. 필요하면 시트별 분류, 헤더 시작 행, 헤더 줄 수, 마지막 데이터 행과 각 열의 저장 필드를 바꿉니다. 안내·참고 시트는 **이 시트 제외**를 선택합니다.
5. 다시 분석한 뒤 원문과 후보를 대조하고 **검토한 내용 저장**을 누릅니다.

같은 이름의 열이나 이름이 없는 열은 A·B 등 위치로 연결합니다. 헤더가 아예 없으면 시작 행을 첫 데이터 행으로, 헤더 줄 수를 0으로 지정하고 제목 열을 선택합니다. 임의의 열 이름도 직접 연결할 수 있습니다. 헤더를 변경하면 기존 수동 열 매핑을 비우므로 다시 분석한 뒤 연결을 확인하세요.

## 인식과 보존

| 원본 형태 | 처리 |
|---|---|
| 안내문 아래 표 | 처음 100행에서 헤더 후보를 비교 |
| 여러 줄·병합 헤더 | 최대 3줄을 자동 탐지, 수동 지정은 0~5줄 |
| 여러 시트·다른 이력 종류 | 시트별 분류와 매핑을 독립적으로 지정 |
| 하드 스킬·소프트 스킬·태그 | 원문 후보에 보존한 뒤 대표 역량 선택의 근거로 사용 |
| 쉼표·세미콜론·줄바꿈·세로줄로 나눈 태그 | 원문 기술명은 보존하며, 최종 카드 태그는 지정 역량으로 제한 |
| SOARA 등의 경험 열 | 상황·문제·행동·결과·회고로 연결 |
| 제목 열이 없거나 제목 셀이 빈 경험 | 매핑된 본문에서 로컬 AI로 최대 40자의 요약 제목을 생성. 본문은 보존하고 대표 역량은 지정된 12개 중 근거가 있는 최대 3개로 정리 |
| 경험의 번호·구분·기간 | 원래 열 이름과 함께 상황에 보존 |
| 셀 내부 줄바꿈·서식 있는 텍스트 | 텍스트를 보존하며 한 데이터 행을 한 후보로 처리 |
| 날짜·`000000` 형식의 번호 | 날짜는 ISO 표기, 번호의 앞자리 0은 유지 |
| 수식 | 실행하지 않고 저장된 계산 결과만 읽으며 최신 값 확인 안내 |

읽을 수 없는 수식 결과나 오류 셀은 해당 행만 미분류로 남깁니다. 여러 데이터 행 또는 서로 다른 필드에 걸친 병합은 경험의 경계를 추측하지 않고 직접 검토하도록 안내합니다. 이 경우 원문에서 항목을 추가하거나 원본 데이터 영역을 정리해 다시 업로드할 수 있습니다.

분류·헤더·미연결 열이 애매한 표는 AI가 임의로 해석하지 않습니다. 원문과 미분류 개수를 남기며, 확정된 다른 항목은 저장할 수 있습니다. 제목이 같은 행도 웹 미리보기에서는 별도 후보로 유지합니다. 기존 기록을 갱신할지 새로 추가할지는 저장 전에 선택하세요.

## 범위와 제한

- XLSX만 지원합니다. XLS·암호화 문서는 Excel에서 암호를 해제하고 XLSX로 저장하세요.
- 기본 대상은 보이는 시트입니다. 숨김 시트는 이름을 직접 지정하면 읽을 수 있습니다.
- 파일 10 MiB, 압축 해제 40 MiB, 시트당 10,000개 데이터 행·100열, 추출 텍스트 1 MiB로 제한합니다.
- 한 시트에 서로 다른 표가 여러 개라면 시트 선택과 시작·끝 행으로 한 영역씩 분석하세요.
- 이미지 안 글자·차트는 경험으로 추출하지 않습니다. 사진만 있는 문서는 별도 텍스트가 필요합니다.
- 자동 탐지는 모든 사용자 양식을 확정하지 않습니다. 원본 미리보기와 수동 매핑이 최종 확인 수단입니다.
- 러너 코드를 업데이트한 뒤에는 실행 중인 러너를 재시작해야 합니다.

## 구현과 의존성

`runner/mcp/xlsx-compat.mjs`는 ZIP 압축 해제 크기를 제한하고 XML 네임스페이스 URI를 기준으로 태그와 관계 속성을 정규화한 뒤 ExcelJS에 전달합니다. 셀 본문의 문자열 치환으로 접두사를 제거하지 않습니다.

Node 표준 라이브러리에는 ZIP 컨테이너·네임스페이스 XML 파서가 없으므로, ExcelJS가 이미 설치하던 `jszip@3.10.1`과 `saxes@5.0.1`을 직접 의존성으로 선언했습니다. 전이 의존성 경로에 의존하지 않고 기존 패키지 버전을 재사용합니다. 참고: [JSZip 스트림 API](https://stuk.github.io/jszip/documentation/api_zipobject/node_stream.html), [saxes 네임스페이스 처리](https://github.com/lddubeau/saxes).

`table-layout.mjs`가 헤더·분류를 탐지하고, `tabular.mjs`가 필드에 연결합니다. 웹 설정은 `source_imports.options.sheet_options`, 미리보기는 `measurements.table_previews`에 보관하므로 스키마 변경은 없습니다. MCP도 `header_row`, `header_rows`, `end_row`, `column_map`을 받습니다.

회귀 검증은 `runner/test/excel-layout.test.mjs`, `runner/test/source-imports.test.mjs`, `scripts/test/import-options.test.mjs`에서 서로 다른 합성 양식을 사용합니다. 개인 원본 파일은 저장소 테스트 자산에 포함하지 않습니다.
