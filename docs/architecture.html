Data in the cloud. Execution on your machine.

웹은 작업을 등록하고, 내 컴퓨터의 러너가 구독 CLI로 실행합니다.

읽는 법. 웹의 요청과 첨부 원본은 Supabase에 저장됩니다. 러너가 claim_next_job RPC로 작업을 가져오고 필요한 데이터를 읽습니다. 그림의 JOB / DATA 화살표는 데이터 전달 방향이며, 네트워크 요청은 러너가 시작합니다. 첨부 업로드는 웹을 경유하며, 로컬 MCP는 러너의 가져오기 코드를 공유합니다.

실행과 반환. 일곱 비서는 작업에 설정된 CLI를 사용합니다. STDIO는 로컬 자식 프로세스와의 입력·출력 연결이며, CLI는 해당 AI 제공자에 접속합니다. 러너가 구조화 출력을 검증하고 결과와 이벤트를 Supabase에 저장하면 웹에서 조회할 수 있습니다.

경계. 중앙 영역은 논리적 통합 범위입니다. Supabase는 클라우드, 러너와 CLI는 사용자 컴퓨터에서 실행됩니다. Auth·RLS·기기 승인은 앱 데이터 접근에 적용되며 AI 제공자 인증을 대신하지 않습니다. GitHub Pages는 이 구조를 소개하는 정적 사이트입니다.
