04 / SYSTEM DESIGN · PROCESS

다음 작업이 다시 읽을 수 있는 기억

이 시스템의 지속적인 기억은 사용자가 저장한 업무 데이터와 산출물에 있습니다. 실행 기록은 추적을 돕고, 작업별 컨텍스트는 그중 필요한 자료를 묶습니다.

무엇을 어디에 남기는가

기억의 역할주요 저장소다음 작업에서의 사용
업무 근거experience_cards · profiles · job_posts · research_notes경험·직무·기업 맥락을 작업별 핸들러가 조회합니다.
사용자의 현재 의도essay_projects · essay_revision_requests현재 초안과 수정 요청을 읽습니다. 화면의 미저장 본문이 payload로 전달되면 저장된 초안보다 우선합니다.
구조화된 산출물artifacts초안과 인용 ID, 제공자·위반 정보를 보관합니다. 최근 초안의 인용 ID는 수정 작업에서 필수 근거가 됩니다.
추적 기록agent_runs · run_events실행 상태·오류·사용량과 선택 근거를 남깁니다. 모든 로그를 다음 프롬프트에 자동 주입하지는 않습니다.
작업 입력 묶음로컬 workspaces/<uuid>이번 호출을 위한 파일입니다. 보존된 DB 자료와는 수명·용도가 다릅니다.

수정할 때 유지하는 기억

뮤즈는 수정 요청을 오래된 순서부터 읽고, 현재 초안을 고칩니다. 연결된 기업 조사 자료는 최신 3건까지 가져옵니다. 기존 산출물의 인용 경험 ID를 필수로 유지하고, 인용 목록이 없는 수동 초안은 경험 전체를 필수 집합으로 취급합니다.

이 필수 집합이 컨텍스트 예산을 넘으면 조용히 근거를 버리지 않고 오류로 멈춥니다. 사용자가 경험을 나누거나 고정 선택을 조정해야 합니다.

현재 기억 전략의 범위

현재 작성 경로에는 벡터 DB나 임베딩 기반 검색, 자동 대화 요약 메모리 계층이 없습니다. 저장된 업무 자료를 결정론적 어휘 검색으로 선별합니다. 모델이 한 실행에서 추론한 내용이 곧바로 사용자의 사실 기록이 되는 구조도 아닙니다.

선택한 로컬 백업은 러너가 실행되는 동안 2시간마다 업무 테이블과 첨부 메타데이터를 JSON으로 내보냅니다. Storage 원본·인증정보·작업 큐·상세 이벤트 로그는 포함하지 않으며, 전체 복원이나 시점 일치 백업을 보장하지 않습니다.
