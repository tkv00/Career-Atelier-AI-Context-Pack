03 · CAREER ATELIER 작동 방식 · 작업 순서

로그인은 이어 쓰고, 일은 건별로 새로 시작합니다

러너 로그인과 AI 서비스 로그인은 저장해 다시 씁니다. 하지만 일을 맡길 때마다 새 폴더와 새 실행을 만들며, 앞선 대화 대신 저장된 최신 자료를 읽습니다.

로그인과 작업은 따로 관리합니다

구분저장하거나 실행하는 곳작동 방식
러너 로그인~/.career-atelier/session.jsonSupabase 로그인 정보와 프로젝트 주소를 보관합니다. 다시 연결할 때 프로젝트를 확인하고 갱신된 로그인 정보를 저장합니다.
AI 서비스 로그인각 CLI의 로컬 로그인 저장소사용자가 직접 로그인합니다. 일을 맡기기 전에 구독 계정인지 확인하고 API 키 환경변수는 실행할 때 제거합니다.
한 건의 작업workspaces/<uuid>와 새 CLI 실행일마다 읽을 자료를 새 폴더에 마련합니다. 이전 대화를 이어 가는 옵션은 쓰지 않습니다.

AI 도구마다 확인된 범위가 다릅니다

Codex에는 --ephemeral과 --ignore-user-config를 씁니다. Claude Code와 Antigravity도 매번 새로 실행하지만, Career Atelier가 두 도구 안에 남는 대화 기록까지 자동으로 지운다고 보장하지는 않습니다.

작업 폴더를 나누면 서로 다른 일의 자료가 섞일 가능성이 줄어듭니다. 현재는 일반 비서 작업 폴더를 실행 직후 한꺼번에 지우는 기능이 없습니다. 자료를 가져올 때 잠시 만든 폴더를 지우는 기능과는 다릅니다.

연결이 끊기면 이렇게 처리합니다

저장한 Supabase 로그인이 없거나 만료됐다면 터미널에서 다시 로그인합니다. AI 서비스 로그인을 확인하지 못하면 blocked_auth로 남깁니다. 로그인 파일을 만들 때 권한 0600을 요청하지만, OS 키체인처럼 암호화해 저장하는 것은 아닙니다.

러너는 15초마다 작동 중이라는 신호를 보냅니다. 90초 동안 신호가 없으면 처리 중이던 일을 다시 대기 상태로 돌릴 수 있습니다. 등록한 지 6시간이 지난 일은 만료됩니다. 이 기능이 중간에 끊긴 AI 대화를 복구해 주지는 않습니다.
