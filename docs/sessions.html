03 / SYSTEM DESIGN · PROCESS

로그인은 유지하고, 작업은 새로 시작

러너의 앱 로그인, AI 제공자 로그인, 작업별 CLI 호출은 서로 다른 수명주기를 갖습니다. 작업의 연속성은 저장된 자료를 다시 읽는 방식으로 유지합니다.

세 가지 세션의 수명

구분저장·실행 위치현재 구현
러너의 앱 로그인~/.career-atelier/session.jsonSupabase 액세스·리프레시 토큰과 프로젝트 URL을 보관합니다. 복원 시 프로젝트를 확인하고 갱신된 토큰을 다시 저장합니다.
AI 제공자 로그인각 CLI가 관리하는 로컬 인증 저장소사용자가 직접 로그인합니다. 실행 전에 구독 인증 상태를 검사하고 API 키 환경변수는 자식 프로세스에서 제거합니다.
작업별 실행workspaces/<uuid> + CLI 자식 프로세스작업별 입력 폴더를 구성해 새 프로세스를 호출합니다. 앱은 resume/continue 인자로 이전 대화를 연결하지 않습니다.

제공자별로 보장하는 범위

Codex에는 --ephemeral과 --ignore-user-config를 전달합니다. Claude Code와 Antigravity도 새 비대화형 호출을 사용하지만, 앱이 두 CLI의 내부 대화 기록까지 자동 삭제한다고 보장하지는 않습니다.

작업 폴더의 분리는 서로 다른 작업의 입력이 섞이는 것을 줄이기 위한 것입니다. 일반 비서 작업 폴더 전체를 실행 직후 지우는 공통 정리 정책은 현재 구현에 없습니다. 일부 가져오기 임시 폴더의 삭제와 구분해야 합니다.

연결이 끊겼을 때

러너의 Supabase 세션이 없거나 만료되어 복원에 실패하면 본인 터미널에서 재로그인합니다. CLI 인증 검사 실패는 blocked_auth로 기록됩니다. 세션 파일은 생성 시 권한 0600을 요청하며, OS 키체인처럼 암호화된 저장소라는 뜻은 아닙니다.

러너는 15초마다 하트비트를 보냅니다. 90초 이상 응답이 없는 실행 작업은 큐 회수 대상이며, 생성 후 6시간을 넘긴 작업은 만료됩니다. 이는 끊긴 CLI 대화를 복원하는 기능과는 별개입니다.
