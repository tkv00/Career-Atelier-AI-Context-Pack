# Prompt와 Harness 설계

## Prompt Lab

비서별 시스템 프롬프트를 편집하고 `새 버전 저장`을 누르면 기존 내용을 덮지 않고 버전 번호를 증가시킵니다. 기본 변수는 프로필, 관심 분야, 목표 직무, 경험 카드, 공고, 기업, 문항, 목표 글자 수, 조사 근거, 초안입니다.

좋은 자소서 프롬프트는 문체 지시보다 근거 경계를 먼저 둡니다.

1. 입력으로 허용할 개인 경험과 기업 근거를 명시합니다.
2. 입력에 없는 수치·역할·성과 생성 금지를 선언합니다.
3. 문항의 평가 의도와 목표 글자 수를 줍니다.
4. 출력 구조와 다음 비서에게 전달할 인계 요약을 지정합니다.
5. 검수 비서에는 작성 비서와 다른 관점의 체크리스트를 줍니다.

## Harness Control

하네스는 프롬프트 밖의 실행 규칙입니다.

- 비서별 Codex/Claude Code 배치
- 최대 에이전트 턴과 단계 제한 시간
- 출처 근거 필수 여부
- 초안 전 사용자 승인 여부
- 읽기 전용 샌드박스
- 재시도 0회
- 사용량 한도 시 중지
- API 키와 유료 초과 사용 차단

비용·인증 관련 규칙은 UI에서 해제할 수 없는 안전 고정값입니다.

## 인계 규격

모든 단계는 결과 마지막에 다음 비서용 요약을 작성합니다. 오케스트레이터는 원문 출력과 함께 `agentId`, `provider`, `runId`, 출처 메타데이터를 SQLite에 남깁니다. 다음 단계는 사용자 프로필·경험·선택 공고·현재 자소서·이전 산출물을 한 컨텍스트로 받습니다.

## 추천 운영 방식

- 뉴스·채용 조사 프롬프트는 짧게 유지하고 날짜와 URL을 강제합니다.
- 기업 조사는 Claude Code, 초안 작성은 Codex처럼 서로 다른 모델을 섞어 관점 편향을 줄입니다.
- 경험 카드는 STAR를 그대로 길게 쓰기보다 사실·내 행동·측정 결과를 분리합니다.
- 검수 결과를 곧바로 덮어쓰지 말고, 문서 보관함에서 사람이 선택해 반영합니다.
