# MCP 구축 결정 로그 (2026-09-03, 자율 작업)

사용자가 취침 중인 상태에서 진행한 작업이다. 요구사항 5번("모든 결정은
너가 하고 기록으로 남겨라")에 따라 **내린 결정과 그 근거**를 여기 남긴다.
결과 수치는 [MCP-BENCHMARK.md](MCP-BENCHMARK.md)에 따로 정리한다.

받은 요구사항 7개를 그대로 옮겨 둔다 — 나중에 이 문서만 읽어도 무엇을
요구받았는지 알 수 있어야 한다.

1. Notion MCP 또는 내 서비스 자체 MCP를 만든다.
2. MCP를 통해 외부의 경험 정리본·기본정보(학교·학점·활동내역 등)를 한 번에 가져온다.
3. 단순 에이전트 사용이 아니라 **토큰 소비량을 줄이기 위함**이다.
4. 가져와서 내 서비스에 알맞은 데이터베이스에 바로 저장한다.
5. 모든 결정은 대신 내리고 기록으로 남긴다.
6. MCP 구축 before/after를 비교해 **실제 토큰 소모량을 정량 지표로** 남긴다(포트폴리오용).
7. **MCP를 구축할 수 없다면 그 즉시 중단한다.**

<br>

## D0. 요구사항 7번 게이트 — 진행 가능 판정

가장 먼저 판정해야 하는 항목이라 제일 먼저 확인했다. 결론은 **진행**이다.

측정한 사실:

| 확인 항목 | 결과 | 확인 방법 |
|---|---|---|
| Node 런타임 | v26.5.0 | `node -v` |
| Supabase 자격증명 | 있음 (`runner/.env`) | 파일 존재 + 값 마스킹 출력 |
| 러너 세션 유효성 | **유효** — 소유자 계정으로 인증 성공 | 실제 `auth.setSession` 후 RLS 조회 성공 |
| 대상 테이블 | 10종 전부 존재·조회 가능 | 실제 `count` 쿼리 |
| Notion 자격증명 | **없음** | env·`~/.claude.json`·`claude_desktop_config.json`·리포 전수 검색 |

`experience_cards` 1행, 나머지 9종 0행인 상태에서 시작했다.

**Notion 자격증명이 없다는 사실이 7번을 발동시키는가 — 아니라고 판단했다.**
요구사항 1번이 "Notion MCP **또는** 내 서비스 자체 MCP"로 선택지를 열어
뒀고, MCP 서버 자체를 만드는 데 필요한 것(런타임·DB 자격증명·대상 스키마)은
전부 갖춰져 있다. 막힌 것은 "MCP 구축"이 아니라 "Notion이라는 소스 하나의
자격증명"이다. 후자는 사용자가 깨어나서 통합 토큰을 발급하면 풀리는,
코드와 무관한 설정 문제다.

다만 이 구분을 흐리지 않기 위해 아래 D4를 함께 결정했다.

## D1. 무엇을 만드는가 — 서비스 자체 MCP 서버

**결정**: Notion MCP 클라이언트를 붙이는 게 아니라, Career Atelier 자체
MCP 서버를 만든다. 소스(Notion·파일)는 서버 **내부에서** 읽는다.

**근거**: 요구사항 3번이 이 설계를 강제한다. 기성 Notion MCP를 쓰면 페이지
본문이 전부 모델 컨텍스트로 들어온 뒤 모델이 그걸 다시 구조화해 INSERT
인자로 뱉어야 한다 — 원문이 **두 번** 토큰이 된다. 자체 서버가 소스를 직접
읽고 DB에 직접 쓰면 원문은 모델 컨텍스트에 **한 번도** 들어오지 않고,
모델은 "어디서 가져와라"라는 참조와 압축된 영수증만 주고받는다.

토큰을 줄이는 지점이 "에이전트를 잘 쓰는 것"이 아니라 **"원문이 컨텍스트를
통과하지 않게 하는 것"**이라는 게 이 설계의 핵심이다.

<br>

## D2. 어디에 두는가 — `runner/mcp/`

**결정**: 새 최상위 디렉터리가 아니라 `runner/` 아래 하위 디렉터리.

**근거**: 세 가지가 공짜로 따라온다.

1. **보안 경계 상속** — 리포 루트 `.vercelignore`가 `runner/`를 통째로
   제외한다. MCP 서버는 자격증명을 쥐고 DB에 쓰는 로컬 면 소프트웨어라
   러너와 정확히 같은 보안 등급이다. 새 최상위 폴더로 만들면 이 제외를
   따로 챙겨야 하고, 언젠가 빠뜨린다.
2. **의존성 재사용** — `@supabase/supabase-js`가 이미 `runner/node_modules`에
   있다. AGENTS.md "No new dependencies" 규칙을 지키면서 쓸 수 있다.
3. **인증 재사용** — `runner/lib/session-store.mjs`의 세션 파일을 그대로
   읽는다. 러너와 같은 사용자 세션으로 로그인하므로 **RLS를 그대로 적용받고
   `service_role` 키는 여전히 어디에도 없다**(§19.2 #2·#3 유지).

<br>

## D3. MCP 프로토콜을 의존성 없이 직접 구현

**결정**: `@modelcontextprotocol/sdk`를 설치하지 않고 stdio JSON-RPC를 직접 짠다.

**근거**: AGENTS.md의 "표준 라이브러리로 안 되는 이유 없이 새 의존성 금지"
규칙. MCP는 줄바꿈으로 구분된 JSON-RPC 2.0이고, 이 서버가 쓰는 메서드는
`initialize` · `tools/list` · `tools/call` · `ping` 넷뿐이다. SDK를 끌어오면
얻는 것보다 잠기는 것(버전 추종 부담)이 크다.

**주의로 남길 것**: stdout은 JSON-RPC 전용이다. 로그를 한 줄이라도 stdout에
쓰면 클라이언트의 프레이밍이 깨진다 — 모든 로그는 stderr로 보낸다.

<br>

## D4. 소스 어댑터를 둘로 나눈다 (file 동작 / notion 자격증명 대기)

**결정**: 파싱·매핑·저장 파이프라인은 하나로 두고, 그 앞단의 "가져오기"만
어댑터로 분리한다. `file` 어댑터는 오늘 밤 동작하고, `notion` 어댑터는
코드를 작성하되 자격증명이 없어 **실호출 검증은 하지 못한 상태로 표시**한다.

**근거**: 이렇게 하면 오늘 밤 파이프라인 전 구간(파싱 → 매핑 → 검증 → 실제
Supabase 저장)을 **진짜로** 검증할 수 있다. Notion 어댑터는 같은 파이프라인의
입력을 만드는 함수 하나로 좁혀지므로, 사용자가 토큰만 넣으면 나머지는 이미
검증된 경로를 탄다.

이 프로젝트의 검증 기준("typecheck는 검증이 아니다, 실제로 돌려 봤는가")을
지키려면 **검증 못 한 것을 검증했다고 쓰지 않는 것**이 중요하다. Notion
경로는 미검증으로 명시한다.

<br>

## D5. 파싱은 결정론적으로 — LLM 폴백 없음

**결정**: 정리본 → 구조화는 정규식·문자열 처리만 쓴다. 애매하면 그 항목을
`skipped`로 반환하고 이유를 붙인다. LLM을 부르지 않는다.

**근거**: `docs/DESIGN-V2-CLOUD.md` §19.2 #4가 "문항 파싱 실패 시 LLM 폴백"을
명시적으로 금지한다. 같은 정신이고, 무엇보다 **LLM을 부르면 이 작업의 목적
자체(토큰 절감)가 무너진다.**

<br>

## D6. 기본값은 dry-run — 쓰기는 명시적으로만

**결정**: 임포트 툴의 `dry_run` 기본값을 `true`로 둔다. 실제 INSERT는
호출자가 `dry_run: false`를 명시해야 일어난다.

**근거**: 이 DB에는 사용자의 실제 지원 데이터가 들어간다. MCP 툴은 모델이
자동으로 부를 수 있는 표면이므로, 기본값이 쓰기면 오호출 한 번이 곧 오염이다.
읽고 → 무엇이 들어갈지 보고 → 승인하고 → 쓰는 순서를 기본값으로 강제한다.

<br>

## D7. 테스트 데이터를 사용자의 실제 DB에 남기지 않는다

**결정**: 쓰기 경로 검증은 실제 Supabase에 실제로 INSERT해서 확인하되,
검증 직후 **삽입한 행을 전부 삭제해 원상복구**한다. 검증 전후 행 수를 함께
기록한다.

**근거**: 두 가지를 동시에 지켜야 했다. ① 이 프로젝트의 검증 기준은 "실제로
돌려 봤는가"이므로 쓰기 경로를 안 돌려 보고 완료라 할 수 없다. ② 그런데
소스가 없는 상태에서 만든 표본은 **지어낸 경험 데이터**다. 자소서 근거로
쓰이는 테이블에 가짜 경험이 남으면 이 앱이 막으려는 바로 그 사고(§14)를
내가 저지르는 셈이 된다.

그래서 "실제로 쓰고, 확인하고, 지운다". 표본에는 `[MCP-TEST]` 접두사를 붙여
혹시 남더라도 즉시 식별 가능하게 했다.

<br>

## D8. 토큰 지표를 "추정"이 아니라 "실측 + 명시된 환산"으로 만든다

**결정**: 1차 지표는 **문자 수·바이트 수(정확한 실측값)**, 2차 지표는 그로부터
공개된 공식으로 환산한 토큰 추정치로 한다. 토큰 수를 단일 숫자로 뭉뚱그려
제시하지 않는다.

**근거**: 이 프로젝트는 API 키를 쓰지 않으므로 공식 토크나이저를 호출할
경로가 없다(그리고 그걸 위해 API 키를 들이는 건 §19.2 #11 위반이다).
그렇다고 출처 없는 토큰 숫자를 포트폴리오에 적는 건 더 나쁘다.

**"before"를 정직하게 만드는 방법**이 이 결정의 핵심이다. 에이전트 방식의
토큰량을 상상해서 적지 않고, **실제로 생성된 행들을 에이전트가 INSERT
인자로 뱉었어야 할 형태 그대로 직렬화해서** 그 길이를 잰다. 즉 before의
분자는 가정이 아니라 같은 입력에서 파생된 실제 문자열이다.

환산 계수는 문자 클래스별로 나눠 적용하고 계산식을 문서에 그대로 적는다
(한글 음절 / CJK / ASCII / 공백·문장부호). 검증자가 같은 입력으로 같은
숫자를 재현할 수 있어야 한다.

## 작업 중 잡은 결함 2건

**1. 내가 만든 서버의 버그 — 비동기 툴 응답이 잘렸다.**
`stdin`의 `end`에서 곧바로 `process.exit(0)`을 부르고 있어서, DB를 오가는
`db_snapshot`이 응답을 내기 전에 프로세스가 죽었다. 메시지를 파이프로 한꺼번에
밀어 넣었을 때만 재현돼서 손으로 하나씩 칠 때는 안 보였다. 처리 중인 요청을
세어 두고 전부 끝난 뒤에 종료하도록 고쳤고, 3건 동시 요청으로 재검증했다.

이 프로젝트가 "typecheck는 검증이 아니다"라고 적어 둔 이유를 그대로 겪은 셈이다.

**2. 원래 있던 스키마 결함 — `gpa_scale`이 만점 100을 못 담는다.**
`education_records.gpa_scale`이 `numeric(4,2)`(상한 99.99)인데 마이그레이션
`0020` 주석은 만점 예시로 "100"을 들고 있다. 직접 넣어 보니
`numeric field overflow`로 INSERT가 깨진다. 백분위 학점 사용자는 학력 저장이
실패한다는 뜻이다.

MCP 쪽은 `safeNumeric()`으로 막고 경고로 올려 임포트 전체가 깨지지 않게 했지만,
근본 해결은 컬럼을 넓히는 마이그레이션(`numeric(5,2)`)이다. **자는 사이에
스키마를 임의로 바꾸지 않았다** — 마이그레이션은 append-only이고 타입 재생성이
따라붙어, 깨어 있을 때 판단할 문제라고 봤다.

## 이 세션에서 만지지 않은 동시 변경

작업 중 `git status`에 내가 건드리지 않은 파일 3개가 수정된 채로 나타났다.

```
M runner/index.mjs
M web/app/(app)/essays/actions.ts
M web/app/(app)/essays/[id]/editor-client.tsx
```

파이프라인 체인(솔 → 뮤즈 → 렌즈 → 콤마 자동 연쇄)을 붙이는 변경이다.
세션 시작 시점의 `git status`에는 없었으므로 **이 세션 도중에 생겼고, 내가
만든 것이 아니다.** 같은 시각에 `experience_cards`에도 행이 하나 늘었다
(`파이프라인검증-경험`, 07:46 KST).

**아무것도 커밋하지 않았고 이 파일들을 건드리지도 않았다.** 그대로 남아 있다.

## 미해결로 남기는 것

정직하게 남긴다. 아래는 이 세션에서 **해결하지 못했다**.

- **Notion 실호출 검증** — 자격증명이 없어 한 번도 호출하지 못했다. 어댑터
  코드는 Notion API v1 문서 형태에 맞춰 작성했으나 실제 응답으로 대조하지
  않았다. 사용자가 토큰을 넣고 첫 호출을 할 때 필드 이름이 어긋날 가능성이
  남아 있다.
- **사용자의 실제 정리본 형식 미확인** — "외부에 있는 경험 정리본"이 어떤
  형식인지 볼 수 없었다. 파서는 흔한 Markdown 관행에 맞춰 설계했고, 형식이
  다르면 파서 규칙을 고쳐야 한다. 이건 파서 실패로 조용히 넘어가지 않고
  `skipped` 목록으로 드러나게 만들어 뒀다.
