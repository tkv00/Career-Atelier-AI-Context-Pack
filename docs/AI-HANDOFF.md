# Career Atelier — AI 인수인계 문서

이 문서는 Career Atelier를 처음 전달받은 AI가 제품의 목적, 절대 제약, 구조, 검증 기준을 한 번에 이해하도록 만든 기준 문서다. 기능을 수정하기 전에 이 문서와 `README.md`, `docs/PRIVACY-AND-COST.md`를 먼저 읽는다.

## 1. 제품을 한 문장으로 설명하면

Career Atelier는 이미 구독 중인 ChatGPT/Codex와 Claude Code의 **로컬 로그인 세션만** 이용하여 뉴스 조사 → 맞춤 채용공고 탐색 → 기업 조사 → 사용자 승인 → 자소서 작성 → 교차 검수를 연결하는 개인용 로컬 웹 앱이다.

핵심 가치는 다음 세 가지다.

1. 추가 API 과금 없이 사용자의 기존 구독을 활용한다.
2. 경험, 조사 결과, 프롬프트, 자소서 버전을 사용자의 컴퓨터에 보존한다.
3. 다섯 고양이 비서의 협업 과정을 화려하지만 업무 도구다운 화면으로 보여 준다.

## 2. 사용자가 가장 중요하게 여기는 것

- 추가적인 토큰 단위 API 비용이 발생하면 안 된다.
- 개인 Codex, ChatGPT, Claude Code 구독을 그대로 사용해야 한다.
- 프롬프트와 하네스를 사용자가 직접 수정해 자신만의 자소서 작성 방식을 발전시킬 수 있어야 한다.
- 자소서는 계속 편집 가능해야 하며 공백 포함/제외 글자 수를 모두 보여 줘야 한다.
- 개인 경험은 STAR 구조와 성과 수치, 역량 태그로 정리해 재사용할 수 있어야 한다.
- 다른 컴퓨터에서도 소스 폴더와 백업 데이터를 옮겨 이어서 사용할 수 있어야 한다.
- 화면의 중심은 귀엽지만 진지하고, 지나치게 캐릭터 상품 같지 않은 고양이 비서들이다.
- 각 비서는 서로 다른 털색을 가지며 실제로 걷고, 일하고, 기다리고, 검수하는 상태 애니메이션을 보여 줘야 한다.

## 3. 절대 바꾸면 안 되는 안전 규칙

아래 항목은 일반적인 구현 취향이 아니라 제품 계약이다. 사용자가 명시적으로 방향을 바꾸기 전에는 변경하지 않는다.

### 반드시 유지

- 동반 서버는 `127.0.0.1`에만 바인딩한다.
- Codex는 ChatGPT/OAuth 구독 로그인, Claude Code는 Claude/OAuth 구독 로그인일 때만 실행한다.
- AI 자식 프로세스에서 OpenAI, Anthropic 및 클라우드 AI 제공자 API 환경변수를 제거한다.
- API 키 또는 판별할 수 없는 인증은 `blocked_auth`로 중단한다.
- Claude 유료 초과 사용 신호는 `blocked_paid_overage`로 중단한다.
- 구독 사용량 한도는 우회하지 않고 `waiting_for_reset`으로 기록한다.
- 로그인 토큰, 비밀번호, API 키는 브라우저, SQLite, 백업 파일에 저장하지 않는다.
- 데이터 가져오기는 삭제 없는 비파괴 병합이어야 한다.
- `local-data/`는 공유 파일, Git, AI 컨텍스트 팩에서 제외한다.
- 실제 AI를 호출하지 않는 격리된 모의 CLI로 전체 흐름을 검증할 수 있어야 한다.

### 하지 말 것

- OpenAI API, Anthropic API 또는 종량제 대체 경로를 추가하지 않는다.
- API 키 입력란이나 브라우저 인증 전달 기능을 만들지 않는다.
- Claude의 유료 초과 사용을 자동으로 켜지 않는다.
- 구독 사용량 제한을 여러 계정이나 API로 회피하지 않는다.
- 사용자 승인 없이 Supabase나 공개 서버로 개인 데이터를 전송하지 않는다.
- 자소설닷컴 계정에 자동 로그인하거나 자동 저장하지 않는다.
- 검증 중 실제 Codex/Claude 호출로 구독 사용량을 소비하지 않는다.

## 4. 시스템 지도

```text
브라우저 UI · http://localhost:3000
  ├─ 고양이 사무실 / 파이프라인
  ├─ 경험 보관함 / 채용 보드
  ├─ Prompt Lab / 문서 보관함 / 설정
  └─ HTTP JSON
        ↓
로컬 동반 서버 · http://127.0.0.1:48620
  ├─ 구독 인증 및 비용 잠금
  ├─ 파이프라인 오케스트레이션 / 승인 / 취소
  ├─ Codex CLI ── 로컬 ChatGPT 구독 로그인
  ├─ Claude Code ── 로컬 Claude 구독 로그인
  └─ SQLite · local-data/career-atelier.sqlite
        ├─ 프로필 / 경험 / 채용공고 / 기업 조사
        ├─ 프롬프트 / 하네스 / 자소서 버전
        └─ 실행 / 이벤트 / 에이전트 인계 산출물
```

UI는 웹 기술로 만들었지만 제품은 SaaS가 아니라 로컬 애플리케이션이다. 구독 세션을 중앙 서버에 옮기지 않는 것이 공개 배포보다 우선한다.

## 5. 에이전트와 인계 흐름

| 순서 | 비서 | 색상/성격 | 실행기 | 책임 | 다음 단계에 넘기는 내용 |
|---|---|---|---|---|---|
| 1 | 루미 | 은회색, 차분한 리서처 | Codex | 관심 분야 뉴스 조사 | 날짜, 출처, 핵심 변화, 채용 준비 시사점 |
| 2 | 모카 | 주황색, 실용적인 스카우트 | Codex | 맞춤 채용공고 탐색 | 원문 URL, 적합도, 경험 매칭, 부족 역량, 우선순위 |
| 3 | 솔 | 크림색, 신중한 분석가 | Claude Code | 기업·직무 조사 | 공식 근거, 기업 과제, 직무 요구, 자소서 재료 |
| 4 | 뮤즈 | 흰색, 절제된 작가 | Codex | 근거 기반 자소서 작성 | 초안, 사용 근거, 작성 판단, 인계 요약 |
| 5 | 렌즈 | 턱시도, 엄격한 검수자 | Claude Code | 교차 검수 | 사실 오류, 과장 위험, 직무 적합성, 수정 제안 |

기본 파이프라인은 순차 실행이다. 각 출력은 `artifacts`에 저장된 뒤 다음 비서의 컨텍스트에 들어간다. 기업 조사 후 하네스의 `approvalBeforeDraft`가 켜져 있으면 `approval_required`에서 멈추고, 사용자가 승인한 뒤 같은 파이프라인을 작성 단계부터 재개한다.

채용 탐색 결과의 `<jobs_json>` 블록은 서버가 파싱한다. 검증된 HTTP(S) URL이 있는 공고만 `job_posts`에 저장하며, 동일 URL은 중복 생성하지 않고 갱신한다.

## 6. 주요 화면과 기능

- **사무실**: 다섯 비서의 위치, 동작, 상태, 현재 실행을 시각화한다.
- **파이프라인**: 단계별 실행, 승인, 취소, 인계 산출물과 상태를 보여 준다.
- **경험 보관함**: STAR, 성과 수치, 역량 태그, 검색/필터, 완성도, AI용 컨텍스트 복사를 제공한다.
- **채용 보드**: 수동 등록과 모카의 자동 등록 공고를 관리한다.
- **Prompt Lab**: 에이전트 프롬프트 버전과 하네스 설정을 편집한다.
- **문서 보관함**: 회사별 자소서 프로젝트, 편집, 버전 메모, 공백 포함/제외 글자 수, 자소설닷컴 복사를 제공한다.
- **설정**: 인증 상태, 안전 잠금, 전체 JSON 내보내기, 비파괴 병합 가져오기를 제공한다.

## 7. 데이터 모델

| 테이블 | 역할 |
|---|---|
| `settings` | 앱 설정과 안전 잠금 |
| `profiles` | 사용자 프로필과 관심 분야 |
| `experience_cards` | STAR 경험, 수치, 태그 |
| `job_posts` | 채용공고와 적합도/상태 |
| `research_notes` | 뉴스 및 기업 조사 원문 |
| `prompt_templates` | 에이전트별 현재 프롬프트 |
| `prompt_versions` | 프롬프트 변경 이력 |
| `harness_configs` | 실행기, 최대 턴, 제한 시간, 출처, 승인 규칙 |
| `essay_projects` | 회사/직무별 자소서 프로젝트 |

SQLite는 WAL 모드를 사용한다. 전체 내보내기는 JSON이며 인증 정보는 포함하지 않는다. 가져오기는 한 트랜잭션에서 병합하고, 내용이 다른 자소서 버전 번호 충돌은 새 버전으로 보존한다. 가져온 설정과 무관하게 구독 전용/키 차단/유료 초과 차단은 다시 강제한다.

## 10. 실행과 검증

필요 조건: Node.js 22.13 이상, Codex CLI, Claude Code, 각 구독 계정의 로컬 로그인.

```bash
npm install
npm run dev
```

검증 순서:

```bash
npm run lint
npm run verify
```

`npm run verify`는 빌드와 함께 모의 CLI를 사용해 로컬 저장, 경험 보관함, 채용 자동 등록, 승인 게이트, 다섯 단계 인계, 취소, 백업/병합, 비용 잠금을 검사한다. 실제 AI 호출은 하지 않는다.

화면을 바꿨다면 데스크톱과 모바일에서 직접 확인한다. 확인할 핵심은 콘솔 오류, 가로 넘침, 고양이 프레임 잘림, 상태와 애니메이션 불일치, 버튼의 실행/취소 전환이다.

## 11. 다른 AI의 안전한 작업 절차

1. 이 문서와 관련 문서를 먼저 읽는다.
2. 요청과 관련된 소스만 탐색하고 `local-data/`를 열거나 출력하지 않는다.
3. 기존 안전 규칙과 비파괴 병합 의미를 보존하는 최소 범위 변경을 한다.
4. 스키마 변경 시 기존 DB의 마이그레이션과 백업 호환성을 함께 설계한다.
5. AI 실행 코드를 변경했다면 인증 검사, 환경변수 제거, 취소, 한도 상태를 함께 검토한다.
6. `npm run lint`와 `npm run verify`를 통과시킨다.
7. UI 변경은 데스크톱/모바일 화면으로 확인한다.
8. 최종 보고에는 변경 파일, 사용자에게 달라진 점, 검증 결과, 남은 제한을 적는다.

## 12. 완료 기준

변경은 다음 조건을 모두 만족해야 완료다.

- 요청한 기능이 실제 UI와 로컬 저장 흐름에서 동작한다.
- 추가 API 과금 경로가 생기지 않는다.
- 인증 정보와 개인 데이터가 노출되지 않는다.
- 기존 데이터의 삭제나 조용한 덮어쓰기가 없다.
- 승인/취소/한도 상태가 실패와 올바르게 구분된다.
- 프롬프트와 자소서 버전 이력이 유지된다.
- `npm run lint`와 `npm run verify`가 통과한다.
- 시각 변경은 데스크톱과 모바일에서 확인된다.

## 13. 현재 범위와 알려진 한계

- 다른 컴퓨터 사용은 소스 복사 + JSON 내보내기/병합 방식이다. 실시간 동기화는 아니다.
- 새 컴퓨터에도 Node.js, Codex CLI, Claude Code 설치와 개별 구독 로그인이 필요하다.
- Supabase와 공개 배포는 사용하지 않는다.
- 자소설닷컴은 본문 복사와 사이트 열기까지만 자동화하며 최종 붙여넣기/저장은 사용자가 한다.
- 뉴스, 채용, 기업 조사는 CLI의 검색 능력과 구독 사용량에 영향을 받는다.
- 구독 한도에 도달하면 재설정까지 기다리며 API 대체 경로가 없다.
- 웹과 동반 서버 포트는 현재 각각 `3000`, `48620`으로 정해져 있다.
- `.openai/hosting.json`이 있어도 로컬 구독 인증이라는 제품 원칙 때문에 공개 호스팅을 기본으로 간주하지 않는다.
