# 기능별 사용 가이드

[처음 설치하기](../README.ko.md#시작하기) · [전체 기능·화면 자료](REFERENCE.ko.md)

현재 웹의 왼쪽 메뉴 이름을 기준으로 설명합니다. `/dashboard` 같은 경로는 본인이 실행한 웹 주소 뒤에 붙는 경로입니다. 가입 직후에는 데이터가 비어 있는 것이 정상입니다.

## 1. 경험과 이력부터 저장하기

**이력 정보(`/records`)**에는 학력·경력·자격증처럼 사실 중심의 기록을 입력합니다. **경험 카드(`/experiences`)**에는 자소서에 사용할 구체적인 사건을 입력합니다. 경력 한 줄을 저장했다고 경험 카드가 자동으로 생기는 것은 아닙니다.

1. 이력 정보에서 필요한 기록 종류를 선택하고 실제 내용을 입력·저장합니다.
2. 경험 카드에서 경험을 추가하고 상황, 판단, 행동, 결과를 적습니다. 확인하지 않은 수치나 성과를 채우지 않습니다.
3. 주제·역량을 나타내는 해시태그를 붙입니다. 하나의 경험에 여러 태그를 사용할 수 있습니다.
4. 저장 후 카드를 다시 열어 내용이 남아 있는지 확인합니다.

태그별 행성은 관련 경험을 탐색하기 위한 화면입니다. 행성을 선택해 경험을 찾고 확대·축소하면서 탐색할 수 있습니다. 파일을 가져오려면 별도의 [MCP 안내](../runner/mcp/README.md)를 사용하세요. 현재 웹에서 임의의 엑셀을 업로드해 자동 정리하는 버튼은 없습니다.

## 2. 비서가 사용할 AI와 문체 설정하기

**프롬프트(`/prompts`)**에서 비서별 AI 제공자·모델·작성 지침을 설정합니다.

1. 로컬에서 로그인한 CLI 제공자를 확인합니다.
2. 사용할 비서를 선택하고 그 제공자로 설정합니다. CLI 하나만 쓴다면 실행할 모든 비서에 같은 제공자를 지정하세요.
3. 지침을 수정하고 저장합니다. 예: “내 판단과 행동을 먼저 설명하고, 확인된 수치만 사용하며, 짧은 문장으로 작성한다.”
4. 저장 후 새 작업을 요청해 결과를 비교합니다. 진행 중인 작업에 소급 적용되지 않습니다.

이 설정은 Career Atelier가 실행하는 작업에 적용됩니다. ChatGPT·Claude 웹사이트의 개인 설정이 변경되는 것은 아닙니다. 프롬프트로 실행 안전 제한을 해제할 수는 없습니다.

## 3. 뉴스와 채용공고 찾기

**관제실(`/dashboard`)**에서 목표 직무와 관심 분야를 먼저 저장합니다. 승인된 Runner가 켜져 있고 해당 제공자의 CLI가 로그인되어 있어야 합니다.

- 루미는 관심 분야 뉴스를 조사합니다. 결과의 제목·날짜·출처 링크를 확인합니다.
- 모카는 지원할 채용공고를 찾습니다. 회사·직무·마감일과 원문을 확인하세요. 날짜가 없는 공고에 임의의 마감일이 생기지는 않습니다.

버튼을 누른 뒤 비서가 즉시 완료되지 않으면 **실행 기록(`/activity`)**에서 요청 상태를 확인하세요. 같은 작업을 여러 번 누르기 전에 기존 요청이 대기 중인지 살펴봅니다.

## 4. 공고를 저장하고 자소서 편집기로 이동하기

**지원 일정(`/calendar`)**이 자소서 편집기의 주요 진입점입니다.

1. **+ 직접 일정 입력**을 누르거나 **에이전트가 조사한 채용공고** 목록에서 공고를 고릅니다.
2. 회사명, 지원할 직무, 마감일 등을 확인하고 **캘린더에 저장**을 누릅니다.
3. 저장한 공고의 **자소서 쓰기** 또는 편집 영역의 **자소서 작성 연결**을 누릅니다.
4. 해당 공고의 자소서 편집기(`/essays/…`)가 열리는지 확인합니다.

일정만 추가하고 자소서 화면을 찾지 못했다면 저장된 공고 목록의 버튼을 사용하세요. 제출 여부와 전형별 결과는 지원 일정에서 실제 진행에 맞춰 갱신합니다.

## 5. 조사 → 초안 → 검수 → 소제목 실행하기

먼저 경험 카드, 사용할 AI 제공자, 승인된 Runner를 준비합니다.

1. 자소서 편집기에 문항과 글자 수를 입력합니다.
2. 기업·직무·공고 내용과 필요한 참고 자료를 입력합니다.
3. **기업 조사부터 소제목까지 실행 (솔)**을 누릅니다.
4. 솔의 조사, 뮤즈의 초안, 렌즈의 검수, 콤마의 소제목 결과를 차례로 확인합니다.
5. 근거가 된 경험이 실제 본인 경험인지, 글자 수와 문항 의도에 맞는지 검토하고 수정합니다.

모카는 이 연쇄 실행에 포함되지 않습니다. 공고를 찾은 뒤 작성할 대상을 사용자가 고릅니다. 경험 카드가 없으면 뮤즈에서 중단됩니다. 중간 실패는 실행 기록에서 이유를 확인한 뒤 해결하고 다시 요청하세요. 자동 검수도 사실 확인을 대신하지 않으며 서비스가 지원서를 자동 제출하지 않습니다.

## 6. 면접 준비

**면접 준비(`/interviews`)**에서 사용할 경험·자소서 등 자료를 준비하고 에코의 질문 생성을 요청합니다. 생성된 질문을 확인하며 답변을 정리합니다. 경험을 수정했다면 이전 질문이 갱신됐다고 가정하지 말고 새 요청의 결과를 확인하세요.

## 7. 작업 상태 읽기

| 상태 | 의미 | 할 일 |
|---|---|---|
| 대기 | 요청은 저장됐지만 아직 실행 전 | Runner 실행·기기 승인 확인 |
| 실행 | Runner가 처리 중 | 완료를 기다리고 터미널 오류 확인 |
| 완료 | 결과가 기록됨 | 요청한 기능 화면에서 내용을 검토 |
| 실패 | 작업을 끝내지 못함 | 오류에 따라 CLI 로그인·제공자 설정·입력 자료 확인 |

Runner가 연결돼 있어도 요청이 없으면 비서는 대기합니다. 웹을 Vercel에 배포해도 AI는 로컬 Runner에서 실행됩니다. AI 없이 입력·수정하는 웹 기능과 AI 생성 기능의 준비 조건을 구분해 주세요.

## 베타테스트에서 확인할 목표

신규 사용자에게 설명을 덧붙이기 전에 아래 과제를 시도하게 해 보세요. 관찰값을 남기고 결과를 임의로 채우지 않습니다.

| 과제 | 성공 기준 | 기록할 값 |
|---|---|---|
| 설치 | 경험 하나 저장 후 새로고침해 유지 | 시작~완료 시간, 막힌 단계, 도움 요청 횟수 |
| AI 연결 | 요청 한 건의 완료 결과 확인 | 로그인 혼동 횟수, 승인 누락 여부 |
| 자소서 시작 | 지원 일정에서 편집기로 진입 | 찾는 데 걸린 시간, 잘못 누른 메뉴 |
| 가져오기 | 누락을 검토하고 대상 기록 저장 | 매핑 수정 횟수, 누락 필드, 완료 시간 |

기존 README와 새 README는 비슷한 숙련도의 서로 다른 사용자에게 배정하는 편이 학습 효과를 줄입니다. 같은 사람이 두 번 설치한다면 순서를 교차하고 그 한계를 기록하세요. 이 문서 변경만으로 설치 완료율이 개선됐다고 주장할 수는 없습니다.
